# 蓝牙设备接入

Windows BLE / GATT 后端最低支持 Windows 10 2004。`IBluetoothAdapter` / `IBluetoothConnection` 隔离平台 API，Core 不引用 Windows SDK。macOS、Linux 可运行模拟模式，原生蓝牙后端未实现。

## 操作入口

通用波形在所有已接入的电击与震动设备上播放，使用同一规范化格式，在发送时转换，不在波形文件中保存厂商字段。C 通道跟随 A 波形，声控时跟随左输入。泵使用泵控制玩法，传感器不作为输出目标。转换规则见 [统一波形格式](default-waveforms.md)。

「设备原生程序」是独立玩法，可创建多个实例并分配兼容设备，提供：

- 电击器固定程序：各通道编号 1–16，0 为关闭。程序强度由玩法控制。
- 二代电击器频率序列：A/B 各 1–100 项，每项 100 ms，频率 1–100 Hz，脉宽 0–100，支持循环或播放完成后停止。按协商的 GATT 容量在条目边界分包，不提前重复启动尚未完成的包；会话结束前裁剪待发送条目。
- 马达固定程序：程序编号不能超过设备报告的数量。协议不提供固定程序的强度限幅，因此仅提供各通道开关，并要求玩法上限为 100%；需要可调强度时使用通用波形。相同固定程序不会每个刷新周期重复发送，避免重启程序。
- 郊狼 V2 原始脉冲：各通道 X 为 0–31、Y 为 0–1023、Z 为 0–31。通用波形转换使用建议的 Z≤20，原始字段允许完整协议范围。

玩法的「硬件输出选项」提供 YOKONEX 辅助马达模式，以及郊狼 V3 相对强度更新和 A/B 独立硬件上限。辅助马达仅在玩法运行时开启，暂停或结束关闭；使用运动输入时禁止开启辅助马达。V3 相对更新依据最近设备强度计算增加／减少量，带 1–15 循环序号并等待对应 B1，之后才允许下一次更新；保持强度使用序号 0。BF 仅在上限或平衡值改变时发送。连接和停止将 BF 上限设为零，再发送带序号的归零 B0，并等待相同序号且两路为零的 B1。

泵玩法分别设置蠕动泵和水泵时长：0 跟随会话，1–65535 秒独立计时。改变某路方向／开关或时长只重置该路计时；暂停冻结活动时间。持续模式续发一秒指令，定时模式发送剩余秒数；到期关闭对应泵，两路定时输出完成后结束玩法。停止发送全局暂停并查询，等待两个泵均关闭的回报。压力保留无单位原始数值，不标成 kPa；固件时长、实际方向与压力标定仍待实机确认。

选中实体设备，展开「协议控制」选择操作。表单按设备能力过滤，查询项目也按协议过滤；参数有范围限制。爪印提供全部公开触发器参数、最多六个概率事件、参数动态、按键与运动组合、XYZ 范围、灯光、参数重置及角度校准。概率总值超过 200 时按协议从末项开始扣除。角度校准先等待 3 秒，再采集 10 秒；F1 原始范围保留，可按除以 2、向零取整并裁剪到有符号字节的规则填入按键／运动草稿，需要用户发送才生效。事件状态和参数按 24 个事件分别维护；取消不虚构参数归零，只有参数变化回报才更新数值。

灵猫可同时发送压力归零和屏幕方向；压力按有符号小端数除以 100 显示 kPa。负鼠收到 B3 后，在连接支持时自动发送完整 24 字节 B2；也可手动同步。该包需要 MTU≥27，容量不足时明确拒绝，不截断成丢失强度字段的 20 字节包。配置草稿不按设备持久化；设备被玩法占用时禁用配置，后端同样验证所有权。原始状态展开区保留报告字段和连接写入容量，字段缺失不会填造数值。传感器到玩法的自动化规则不属于设备指令，不在协议面板配置。

## 状态、停止与错误

- 两代电击器验证包长、加和校验与字段范围，报告强度、程序、电极接触、辅助马达、计步与原始加速度／陀螺仪。零加速度仍保留原始六轴数据，但不生成有效倾角。兼容二代固件确认版本后才开放灯光切换，并等待灯光状态确认。
- 郊狼 V2 归零后读取强度或等待通知确认。震动器型号回复用于确认协议与通道，不代表物理停止确认；负鼠协议也不保证已归零时再回复。写入成功仅表示系统接受指令。
- 每台连接由独立驱动维护协议缓存和确认状态。命令与输出共用该连接的串行门；后台屏幕同步也经过同一门。停止尝试辅助马达和电击输出两部分，保留两部分错误；固定程序缓存仅在完整发送成功后更新，停止清除缓存。
- 同一设备同时只归一个玩法，暂停保留占用。停止、定时结束、断连及写入故障只影响所属玩法；全部停止、Esc、切换来源或关闭应用停止所有玩法。无法确认停止时保留占用。主动断开即使停止失败，也释放旧 GATT 连接并报告错误；重新连接不恢复输出。
- Windows 使用 WriteValueWithResultAsync，串行执行原生写入和释放，检查协商 MTU，保留原始异常和 HRESULT、包长、权限及 ATT 状态。Core 不依赖 Windows 类型。

## 使用与诊断

设置页选择「蓝牙」并保存，再到工作台连接设备。首次启动使用模拟模式；已保存的蓝牙来源会在下次启动恢复，但不会自动连接或播放。

仅扫描、输出广播总数及相关候选：

```sh
dotnet run --project src/YokoWave.Desktop -- --bluetooth-probe
```

发现且仅发现一台兼容设备时，连接、关闭输出、等待设备确认、读取状态，再断开：

```sh
dotnet run --project src/YokoWave.Desktop -- --bluetooth-probe --connect
```

诊断模式不会发送非零强度。多台设备需通过界面选择，不自动猜选。扫描未发现设备时，先检查开机、距离、系统蓝牙和其他应用是否仍持有连接。

可按协议筛选，仅当筛选后恰有一台设备时连接：

```sh
dotnet run --project src/YokoWave.Desktop -- --bluetooth-probe --connect --profile CoyoteV3
```

可选协议名称见 `BluetoothProtocol`；诊断输出包含名称、协议、信号、GATT 权限和系统错误。传感器探测不发送输出指令。

用本地音频重复验证五次静音媒体初始化、归零、零强度声控会话及停止：

```sh
dotnet run --project src/YokoWave.Desktop -- --bluetooth-probe --connect --zero-audio /path/to/audio.wav
```

此检查将扬声器音量和 A/B 强度固定为 0%，不使用应用保存的强度配置。

Windows 桌面目标会自动使用 `net10.0-windows10.0.19041.0`；非 Windows RID 仍使用通用 `net10.0`。需要在 Windows 上构建通用模拟入口时可设置 `-p:YokoWaveWindowsBluetooth=false`。这只是构建选择，不会给非 Windows 平台增加原生蓝牙能力。

## 验证记录

- **实机连接与状态验证**：在 Windows 上实际发现并连接 `YCY-DJ`，读取电量与电极状态，确认两路输出关闭回报并正常断开。实机确认 `YCY-DJ` 的 FF31 权限为 `WriteWithoutResponse`、FF32 为 `Notify`，协商 MTU 为 512；静音媒体与零强度会话下设备持续回报两路关闭。未发送非零强度，实际物理输出与标定尚未实机验证。旧版 `YYC-DJ` 编码器通过协议测试，尚无实机验证。
- **自动化与替身验证**：自动测试使用 GATT 替身链路核对精确控制包、关闭确认、校验与范围、连接失败释放、故障锁定、后台通知到 UI 的调度、设备来源保存与恢复，以及断连只停止所属玩法的目标。
- **协议测试覆盖**：涵盖郊狼 V2 位字段及示例、V3 四帧 25 ms 样本与停止序号匹配、泵 AES 指令与时长字节序、三通道电机与方向限制、传感器有符号值及截断包、初始化失败释放、停止失败保留占用、多连接隔离、玩法兼容性、界面本地化及配置保存。未对新增设备发送非零硬件输出。
