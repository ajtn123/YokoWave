# 输入与时间处理

输入采集和纯数值处理分开。Core 定义音频／传感器快照，Desktop 负责平台音频，Pipelines 的资源参与者采集输入并交给同步处理器。使用步骤位于应用内「帮助」。

## 平台后端

`MiniAudioInputFactory` / `MiniAudioInputSession` 使用 SoundFlow / MiniAudio，支持本地 WAV、MP3、FLAC（最大 100 MiB）、默认麦克风以及 Windows 默认播放设备的系统声音。macOS / Linux 的媒体及麦克风后端已实现但待平台实测；系统播放捕获限 Windows。测试使用替身，不自动打开麦克风。

Core `AudioFeatureAccumulator` 约每 50 ms 产生左右 RMS 与能量变化特征。扬声器增益只修改媒体播放缓冲，0% 仍解码和分析；静音与非有限采样被归一处理，不改变用于设备映射的特征。dBFS 不表示环境声压或校准的物理输出。

`AudioProcessor` 按音量／节奏跟随、灵敏度、噪声迟滞门和包络求值。环境校准约采集 2 秒，按较高分位估计底噪，只保存参数。实时音频不录音、不落盘、不上传。

## 有效期与生命周期

音频只在运行或显式校准时打开。静音、无回调、超过 2 秒的特征和媒体结束都产生零输出并保留监听，新帧到达后恢复；实际输入错误才停止所属图。暂停清理旧特征并暂停输入，停止／断连／关闭释放资源，停止也可取消未完成的输入启动。会话定时在等待期间继续生效。

`SensorParticipant` 根据设备能力开启运动流、传感器流或状态轮询，从控制器复制已经验证的读数及采集时间。角度、步数、压力、加速度／陀螺仪、按键、事件、电压和强度均为数值端口；设备没有上报的字段保持缺失，不填造默认数据。输入年龄依据采集时间，刷新同一份状态不会延长有效期。跨主机时间转换见 [WebSocket](websocket.md)。

`NumericSignal` 传播有效期、模拟来源和输入序号。明确标识的模拟节点可用于本地测试，但经增益、映射、进度或增强后仍不能驱动真实设备。

## 模板组合

| 模板 | 图组合与状态 |
| --- | --- |
| 滑动 | `TouchProcessor` 输出包络、频率、相对脉宽；松手归零、保持或录制循环。记录最多 256 帧，至少两帧可保存为通用波形。 |
| 禁锢 | 传感器 → 基准偏差 → 范围映射 → 参数映射 → 输出；第一条有效输入建立基准，每条链可独立校准。默认映射 5°–35°。 |
| 运动 | 角度／步数 → 活动计数 → 等待／输出周期 → 波形门控；约 0.7 秒比较变化，等待时活动重置计时，可通过目标计数完成会话。 |
| 固定睡眠剥夺 | 周期门控，默认等待 90 秒、输出 5 秒。 |
| 随机睡眠剥夺 | 每轮选择等待、输出时长和比例；触发本地波形池中的下一条。默认等待 30–90 秒、输出 5–10 秒、比例 50–100%。 |
| 活动重置睡眠剥夺 | 周期增加有效活动输入，活动发生时重新等待。 |

各模板的处理器状态每次启动重新创建。多个计数目标均完成后结束；活动次数不宣称为校准步数。暂停冻结活动时间；周期遇到超过 2 秒的调度空档时重新等待，不补发错过的输出。参数默认值以注册配置为准，实例可编辑并保存为用户模板。

输入启动、取消、无数据等待、恢复、故障回滚和暂停后的传输错误均有行为测试，见[测试](testing.md)。
