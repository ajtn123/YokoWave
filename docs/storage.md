# 本地存储

默认目录为 `Environment.SpecialFolder.LocalApplicationData/YokoWave`；设置页显示解析后的路径，`YOKOWAVE_DATA_DIR` 可覆盖。目录由应用创建，开发隔离方法见 [CONTRIBUTING](../CONTRIBUTING.md#环境与运行)。

## 文件与所有权

| 文件 | 内容 | 实现 |
| --- | --- | --- |
| `workspace.json` | Schema 版本、累计会话数和总时长 | Core `WorkspaceStore` |
| `settings.json` | 语言、本地来源、默认节点上限、计时上限、接触显示、自动连接标识、远程端点元数据、按设备标识的硬件选项 | Core `AppSettings` / `WorkspaceStore` |
| `waveforms.json` | 统一格式的自定义波形，不含内置资产 | Core `WorkspaceStore` / `WaveformAsset` |
| `pipelines.json` | 图实例、节点配置、连线、设备归属与引用、定时及布局 | Pipelines `PipelineStore` |
| `pipeline-presets.json` | 用户子图模板、暴露端口及设备引用 | Pipelines `PipelineStore` |
| `sessions.jsonl` / `sessions.1.jsonl` | 当前与一份滚动旧会话日志 | Core `SessionJournal` |

图与硬件设置分开：节点拥有玩法参数和各自上限，设备硬件设置跨图保留。分组成员列表不等于实际 I/O 资源列表，只有节点引用的设备参与运行。图文件保存稳定类型键及数据，不保存 Nodify 模型、处理器、任务、设备句柄或凭据。

远程端点只保存名称、URL 和连接种类。令牌与证书密码仅在内存，不进入上述文件。音频路径属于节点配置；实时音频不录音、不落盘。

## 保存顺序

文件使用紧凑 JSON。`WorkspaceStore` 在自身异步门内验证并依次写入设置、波形、追加日志，最后更新版本与累计统计；各 JSON 文件通过同目录临时文件替换。单文件替换不等于跨文件事务。

`PipelineStore` 分别保存实例和用户模板，读取失败会阻止覆盖对应文件。节点参数编辑直接更新草稿及实时处理器，保持现有表单对象；保存由工作区协调。硬件修改通过设备页串行更新和持久化，开始会话及关闭前等待待写设置完成。全局设置页仍使用保存按钮；语言选择即时更新并保存。

启动读取图和设置，不自动启动会话或音频。自动连接默认关闭，开启后只尝试已记录且当前可用的来源；远程来源需重新提供内存凭据并接入。重连不恢复输出。

## 会话日志

日志为 UTF-8、无缩进 JSON Lines，每行一条摘要，最大文件大小 128 KiB。追加会超过上限时，将当前日志替换为 `sessions.1.jsonl`，仅保留这一个旧文件。重复保存相同记录不会重复追加。

历史列表来自两份日志中仍保留的记录。累计会话数与总时长写入 `workspace.json`，不因旧日志被滚动删除而减少。单次会话完成只生成一条摘要；已发送峰值只统计成功提交，原始 GATT 透传峰值不作推测。

## 无效数据与重置

- **可识别的旧开发版本**：`1 ≤ SchemaVersion < WorkspaceData.CurrentSchema` 时，删除已知应用数据文件并返回默认状态，不迁移。当前版本常量见 `WorkspaceData`，不在文档维护第二份版本号。
- **损坏、缺少版本、非正版本或较新版本**：保留原文件、报告读取错误并阻止保存。未知版本不会被当作可重置的旧版本。
- **清除本地数据**：设置页确认后，先停止玩法、断开来源并释放资源，再清除已知文件及其临时文件，重建默认界面状态。失败在清理边界报告，不继续伪装为成功。

重置范围包含当前文件名和应用明确识别的旧文件名，不递归删除整个数据目录，保留其他文件。内置波形是嵌入资源，不会被清除。行为回归位于 Storage 与 Ui 的本地数据测试；见[测试说明](testing.md)。
