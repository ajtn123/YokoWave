# 节点玩法

导航中的「节点玩法」提供可运行的数值管线编辑器，使用 Nodify.Avalonia 2.0.0 和 Avalonia 12.1.5。系统字体、明暗主题、强调色以及 en / zh-CN JSON 本地化沿用应用资源。

## 使用

1. 在设备页连接设备，再打开节点玩法。
2. 默认图包含波形、数值、增益和通道输出。选中通道输出，在参数面板选择设备及通道：A=0、B=1、C=2。
3. 选中数值节点，设置强度比例；默认值 0，允许以零强度启动。0.3 表示 30%。波形经增益处理后送到强度端口，频率和相对脉宽单独连线。
4. 从节点库添加节点，拖动端口连接。选中节点后可修改参数；拖动节点或平移、缩放画布，点击「适应画布」查看整图。节点库和参数面板可以收起。
5. 设置玩法上限和可选的秒级定时，开始运行。运行时数值节点可以实时修改，下一帧生效；拓扑、其他配置和设备绑定锁定。暂停归零且保留设备占用。
6. 保存图。复制／粘贴用于当前图内的节点及选中节点之间的连线；支持删除、撤销、重做和 Ctrl+C / V / Z / Y、Delete。打开图不会自动连接设备或开始输出。

## 节点与数值

| 节点 | 输入 | 输出 |
| --- | --- | --- |
| 数值 | 配置中的数值，可实时修改 | value |
| 波形 | 统一波形资产及资产通道 | level、frequency、pulseWidth |
| 增益 | value、gain | value × gain |
| 限幅 | value、limit | 限制到 0..limit 的 value |
| 通道输出 | strength、frequency、pulseWidth、limit | 绑定设备的一个输出通道 |
| 泵输出 | direction、water、peristalticSeconds、waterSeconds | 绑定设备的定时泵命令 |

所有标量端口接受同一种数值信号，无隐式单位换算。强度、相对脉宽和上限使用 0..1，频率使用 Hz。未连接端口使用提示中的默认值；已经连接但缺失、过期、非有限或超出目标范围的参数，使该输出归零等待。处理节点保留原始有效期和模拟来源，模拟信号不能驱动真实设备。

泵方向为整数 0（关闭）、1（正转）、2（反转），水泵开关为 0 / 1，时长为 1..65535 整数秒。变化的采样窗口不能当作离散泵命令。相同参数只发送一次，参数变化或暂停后继续时重新发送定时命令；停止关闭两路泵。该协议没有原生百分比强度或频率控制。玩法上限为 0 时禁用泵，其他比例不能缩放泵流量。

一个图可以绑定多个设备，同一设备在一个图中可以分别有 A/B/C 输出节点。每个通道只允许一个最终输出；跨图及普通玩法之间由同一个设备控制器执行整台设备独占。通道限幅分别计算后合并为一帧，B 的上限不改变 A。

## 执行和存储

`YokoWave.Pipelines` 不引用 Avalonia。`NodeTypeRegistry` 注册配置解析、端口、验证和处理器工厂；UI 的 `PipelineNodeCatalog` 单独注册编辑器。`PipelineCompiler` 检查图结构、节点参数、连接方向、输入数量、循环、重复写入和实际设备能力，生成独立配置及波形快照。

每次启动创建新的处理器实例。`PipelineRuntime` 按拓扑同步求值，每个节点每帧一次。`DeviceOutputCoordinator` 合并数值参数，保留四个间隔 25 ms 的波形样本并在会话期限后归零。`PipelineSession` 使用单独的后台时钟约每 100 ms 提交，实际输出不依赖 UI 定时器；独立设备并行提交，同一设备仍由控制器串行化。

停止先取消后续帧，等待在途提交，再通过公共设备控制器归零和清理；确认成功后释放占用。失败设备保持占用，可点击停止重试。原始输出错误与清理错误同时保留；UI 通知订阅者异常不终止输出循环。每次完成写入一份普通会话摘要，沿用 `sessions.jsonl` 的 128 KiB 单旧文件滚动。

`pipelines.json` 单独保存图定义、布局、设备引用、上限和定时，使用紧凑 JSON 和临时文件替换。文件不包含第三方控件类型、运行时、蓝牙连接或凭据。无法读取的文件不自动覆盖。普通玩法仍使用 `modes.json`。

## 当前范围

节点页面提供上表中的六种节点。普通玩法页面继续提供声控、滑动、播放列表、禁锢、运动、睡眠、原生程序、硬件命令和 WebSocket 等功能；这些功能尚未转换成图节点。子图、用户节点模板、命令／GATT 资源端口、WebSocket 管线统一执行及普通玩法执行层的移除尚未实现。

通道节点通过公共传输层支持本地、模拟及 WebSocket GATT 客户端设备，仍在实际发送时使用已有协议驱动。该版本未进行节点管线的实机输出验证。便携目标已构建，Linux / macOS 的原生画布交互仍需相应系统测试。

## 验证

`PipelineTests` 检查图编译、端口范围、采样窗口、来源与有效期、动态参数、通道合并、后台时钟、暂停独占、故障占用、并行设备提交和停止顺序。

`PipelineUiTests` 使用 Avalonia Headless 验证鼠标选择、数值绑定、实际拖线、复制粘贴、撤销重做、语言与主题切换及保存。截图和 200 节点 / 500 连线的初次创建、渲染和分配测量写入 `artifacts/screenshots/`；该测量不代表真实窗口的持续拖动帧率。
