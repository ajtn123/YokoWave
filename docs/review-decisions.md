# 审查建议的适用性

`artifacts/review/` 中的报告是参考材料。此处说明当前实现对各项建议的取舍；架构细节见 [架构说明](architecture.md)。

| 审查项 | 当前实现与取舍 |
| --- | --- |
| LOG-01：重复初始化阻止构建 | 不适用。`DeviceController` 每个输出成员只初始化一次。 |
| SMELL-01/02/03：会话和感应玩法混杂 | 七种玩法分别持有运行状态，组合轨道、强度、运动采样和周期组件；不需要额外建立另一套 Strategy 接口。 |
| LOG-02：后台事件异常和释放竞争 | 通知通过有异常边界的任务处理，订阅者异常互相隔离；排队通知保留接收时间，释放后忽略，同步门不会在有等待者时销毁。 |
| LOG-03：通道位掩码 | `ChannelCount` 统计实际启用位，`HasChannel` 按位判断且索引限制为 0–2，支持非连续通道。不存在含义不明的 `OutputChannels` 别名。 |
| ARC-01：主视图模型转发与反射 | 控件直接绑定所属玩法或编辑器，播放命令归玩法；主视图模型管理导航、集合和跨玩法协调，不包含属性代理与反射广播。 |
| ARC-02：全局串行门 | 输出、通知、停止和断开按设备 ID 串行，门跨重连保留；批量占用按固定顺序取得全部目标门后校验与占用。连接、扫描、传输切换和释放仍由生命周期门协调。玩法与各目标并行推进，停止等待所有在途写入结束。 |
| ARC-03：传输接口与设备能力 | 传输层管理多种设备，可以实现多个功能接口；控制器和 UI 根据目标 profile 校验灯光、运动和压力复位能力，不以接口存在代替设备支持。电击器与其他设备共用同一传输和 profile 定义。 |
| LOG-04：音频同步清理 | 工厂通过 `await DisposeAsync` 清理，原始与清理异常一起保留。当前后端的释放同步完成，不能据此断言存在死锁。 |
| LOG-05：文件替换重试 | 不使用无差别重试。报告没有共享冲突的复现依据，`IOException` 也可能表示权限或磁盘错误。保存失败显示错误，写入保护、损坏文件保护和日志滚动语义独立保留。 |
| SMELL-04：原生 GATT 发现 | `WindowsGattResolver` 负责服务／特征发现及能力验证，连接构建路径持有资源并统一清理。诊断入口与探针逻辑分别位于 `Program` 和 `DiagnosticProbes`。 |
| PERF-01：波形绘图分配 | 缓存几何和画笔；参数、A/B 波形、相位、显示范围和尺寸参与失效，颜色实时更新。只承诺复用本控件的对象，不承诺整个 UI 零分配，也不采用未经测量的帧率结论。 |
| FMT-01/02/03：压缩语句与清理路径 | 生命周期代码采用一行一条语句和展开的多步骤分支。初始化回滚保留停止和关闭异常，不静默忽略；无关测试文件不做整库排版。 |
| TEST-01：新协议没有测试 | 不适用。测试覆盖 V2 位字段、V3 四帧与停止序号、泵 AES 向量、电机通道、传感器数据及各设备连接生命周期，不需要重复的模板测试。 |

其他抽象边界：

- 玩法状态通过独立运行对象隔离，不额外添加 `SessionExecutionContext`、`PeakTracker` 和 `HardwareLeaseCoordinator`。运动启动失败时，原始错误与停止错误同时保留，停止未确认的设备仍被占用。
- 静态配置可以预先校验；连接、占用和目标能力必须在相应设备门内复核，不能将动态状态校验全部移到锁外。
- 不提供统一 `ValidationRules` 或 `BluetoothBinary`。相似条件包含不同领域范围、舍入与协议编码语义；`BinaryPrimitives` 和协议内函数已能表达这些规则。报告中的泛型去重示例也不能正确处理非集合枚举。
- 测试替身共享定义；并发替身使用线程安全集合和可控阻塞点，不为目录统一引入新的测试工厂体系。
- 名称、编译绑定、调用和测试保持一致，不保留无用途的兼容属性或适配器。配置 JSON 使用当前 Schema。

自动验证使用模拟或替身设备，覆盖稀疏通道、慢设备隔离、多目标写入与停止屏障、相反顺序的原子占用、取消后释放门、通知与释放竞争、异常订阅者、运动启动失败、命令派发和重入、独立玩法推进、缓存刷新，以及协议、界面、本地化和存储行为。
