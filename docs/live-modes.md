# 声控与感应玩法

四种玩法依据参考 APK 的离线控制规则重新实现，沿用玩法独立参数、设备唯一归属、输出上限、暂停、停止和会话定时。每类可创建多个实例，启动应用只恢复预设，不打开输入或恢复输出。

## 声控

| 输入 | 实现与范围 |
| --- | --- |
| 本地媒体 | WAV、MP3、FLAC，最大 100 MiB；边解码边播放，可循环 |
| 麦克风 | 使用系统默认输入设备，开始或主动校准时才采集 |
| 系统声音 | Windows WASAPI 默认播放设备的 loopback；macOS、Linux 暂不支持此来源 |

桌面音频后端使用 [SoundFlow](https://github.com/LSXPrime/SoundFlow) 与 MiniAudio，包含各平台原生库。输入通过接口注入，共享界面和核心控制不依赖音频后端；自动测试使用替身，不打开真实麦克风。

PCM 每 50 ms 形成一次左右声道 RMS／能量变化特征。音量跟随使用分贝幅度，节奏跟随额外使用能量上升量；灵敏度提供增益和带迟滞的噪声门限，包络分别使用较快的上升与较慢的下降。`dBFS` 是数字音频幅度，不是环境声压或实际设备输出量。

环境校准采样 2 秒，以较高分位的音量估计底噪，校准期间不开始设备会话。麦克风和系统输入不保存录音，也不上传；媒体文件只保存原路径与设置，解析完全在本机进行。没有加入原 APK 的云端上传分析、分享或下载接口。

扬声器音量只影响文件播放，不修改输入映射或设备强度。暂停同步暂停媒体／采集并清空旧特征，继续后等待新特征；停止、关闭、断连或真实输入故障释放本实例资源。静音、没有 PCM 回调或音频帧超过 2 秒未更新时输出归零并持续监听，不结束会话、不重复打开输入；收到新帧后恢复响应。媒体播完后显示结束状态，归零等待主动停止，不自动重播。已启用的会话定时仍然生效。

0% 通过最终扬声器缓冲区的增益处理实现静音，解码与特征分析仍继续。原生音频生命周期操作与 PCM 特征处理使用独立同步锁，避免暂停、关闭与采样回调同时修改状态；释放某项资源失败时仍继续释放其他资源。空文件在打开音频设备前被拒绝。

音频、蓝牙与停止失败保留原始内部异常，界面使用本地化文案；完整异常链输出到开发诊断 Trace。原始写入异常与后续停止异常同时存在时会一起保留，停止未确认仍保留设备占用。

## 禁锢

使用设备加速度计的合成倾斜量，首次有效读数建立每台目标设备的运行时基准。基准和运动计数仅在内存中存在，不是设备配置。

- 偏差不超过安全角度时输出为零，默认安全角度为 5°。
- 超出部分除以渐增角度得到强度比例，默认渐增范围为 30°，最终仍受玩法输出上限限制。
- 频率与脉宽参数随比例变化，保留 APK 禁锢模式的映射规则。
- 运行中可重新将当前角度设为基准。

倾斜量按 APK 相同的有符号加速度换算规则计算，不表示完整的三维姿态。角度流使用厂商协议 `0x35 0x14` 开关，`0x35 0x71 0x06` 通知需通过长度与校验检查。计步通知可解析，但不把角度变化计数称为经校准的步行步数。

## 运动模式

等待时每约 0.7 秒比较角度变化，灵敏度越高，检测阈值越低。检测到活动时增加动作计数并重新等待；持续静止达到指定时长后输出指定时长，再进入下一轮等待。默认静止等待 10 秒、单次输出 5 秒。

可选择 A/B 波形，或为两路分别设置波形。可选动作目标在所有目标设备均达到指定次数时结束；会话定时独立生效，手动停止始终可用。输出阶段不会因为新的运动提前重置，暂停和停止仍立即归零。

## 睡眠剥夺

| 模式 | 行为 |
| --- | --- |
| 固定间隔 | 等待后输出指定时长，再重复；默认等待 90 秒、输出 5 秒 |
| 随机间隔 | 每轮从最小／最大范围选择等待与输出时长，按当前强度比例输出，并分别从本地池选取 A/B 波形 |
| 活动重置 | 等待阶段检测到设备角度变化或新的活动计数时，重新开始等待；需要新鲜传感器读数 |

随机默认等待 30–90 秒，输出 5–10 秒，强度比例为当前强度的 50–100%。自动／临时增量先计算，随机比例再缩放，最终按玩法上限裁剪；原本为 0% 的通道仍为零。原 APK 的服务端随机波形请求由玩法自己的本地列表替代，空列表不能开始随机模式。

暂停冻结活动时钟。应用挂起或调度间隔超过 2 秒后重新等待，不补发错过的输出。

## 输入与验证范围

禁锢、运动及活动重置模式只接受新鲜读数。传感器数据缺失、无效或超过 2 秒未更新时归零并等待，恢复后重新计算等待状态。停止时关闭该玩法的角度流并释放目标占用；其他实例继续运行。模拟来源提供明确标记的角度滑块，真实蓝牙连接禁止注入模拟读数。

测试覆盖协议包、基准与角度边界、无输入与过期输入、活动目标、固定／随机周期、暂停、输出上限、输入资源清理、取消启动、多实例隔离和本地化。Windows 原生后端已通过本地 WAV 解码、扬声器音量为零时的特征提取、暂停／恢复检查，没有打开蓝牙连接。

Windows 系统声音输入已验证：连续 4 秒没有 PCM 回调时，输入设备仍处于运行状态，随后主动释放成功。这种空闲状态不作为输入故障，也不生成伪造音频帧。自动测试覆盖长期缺帧、过期帧、静音后新帧恢复、媒体播完等待，以及主动停止和定时结束释放资源。

真实麦克风／系统音频采集、设备角度流及新玩法的实机输出仍需对应设备确认；应用不录制真实音频输入，亦不自动发送非零实机输出。macOS、Linux 音频包含后端实现与原生库，尚未在这些系统实机验证；真实 BLE 后端仍仅支持 Windows。
