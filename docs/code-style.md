# 代码风格

本规范适用于手写 C#、Avalonia XAML 和测试代码。架构与业务约束见 [AGENTS.md](../AGENTS.md) 和 [架构说明](architecture.md)；自动生成代码、外部协议标识和框架要求的签名遵循各自约定。

新增与重构代码遵循本规范。修改已有代码时统一所涉及的职责范围，避免将无关的全文件格式化混入功能提交。`.editorconfig` 定义可自动检查的格式与命名规则，本文定义需要结合语义判断的部分。

## 文件与类型放置

- 目录与命名空间对应，使用文件范围命名空间。文件名匹配主要类型名，如 `PipelineSession.cs`。
- 一个文件以一个主要类型为中心。仅供它使用的小型枚举、记录或嵌套类型可就近放置；有独立职责或被多处使用的类型单独成文件。
- 类型放在负责该行为的模块，避免通用的 `Utils`、`Helpers`、`Common` 目录。共享实现按实际职责命名，如 `PipelineGraphClipboard`。
- `partial` 用于 XAML／生成代码配对、语言或框架要求的分部实现；手写类型优先通过组合拆分职责，不用多个分部文件掩盖过大的类。
- `using` 放在命名空间之前，`System` 在前，其余按名称排序，不插入分组空行。利用已有隐式导入，删除未使用的导入；只在名称冲突时添加别名。
- 默认使用最小可见性。跨程序集调用或 XAML 访问需要时才公开类型和成员，不为测试单独扩大生产 API。

## 成员顺序

类中的成员按以下顺序放置；每组内部按相关性和调用流程排列，不按字母机械排序：

1. 常量、静态只读字段、Avalonia 属性注册字段。
2. 实例字段：先依赖，再同步／生命周期资源，最后可变状态。
3. 属性和命令属性：先公开状态，再派生状态，相关属性相邻。
4. 事件。
5. 构造函数和静态工厂。
6. 对外操作、接口实现与重写方法，生命周期操作按启动、运行、停止、释放排列。
7. 私有事件处理器与辅助方法，调用者在前、被调用者在后。
8. 仅供该类型使用的私有嵌套类型。

小型类型可以省去空的分组；各组不加标题注释或 `#region`。属性的后备字段统一放在字段组，不穿插在方法之间。框架要求的静态初始化顺序优先于上述排版顺序。

```csharp
internal sealed class OutputHistory
{
    private const int Capacity = 100;
    private readonly List<OutputFrame> _frames = [];

    public int Count => _frames.Count;
    public OutputFrame? Latest => _frames.LastOrDefault();

    public void Add(OutputFrame frame)
    {
        _frames.Add(frame);
        Trim();
    }

    private void Trim()
    {
        if (_frames.Count > Capacity)
            _frames.RemoveAt(0);
    }
}
```

## 命名

| 对象 | 规则 | 示例 |
| --- | --- | --- |
| 类型、方法、属性、事件、枚举成员、常量 | `PascalCase` | `DeviceConnection`、`StopAsync`、`MaximumWriteLength` |
| 接口 | `I` + 职责名称 | `IDeviceTransport` |
| 私有实例／静态字段 | `_camelCase` | `_controller`、`_disposeTask` |
| 参数、局部变量、主构造函数参数 | `camelCase` | `deviceId`、`receivedAt` |
| 类型参数 | 简单场景用 `T`，有多个角色时用 `T` + 含义 | `TConfiguration`、`TResult` |
| 布尔属性／判断方法 | 正向的 `Is`、`Has`、`Can`、`Should` | `IsConnected`、`CanEdit` |
| 事件及处理器 | 事件描述发生的事，处理器加 `On` | `StatusChanged`、`OnStatusChanged` |
| 异步操作 | 方法名以 `Async` 结尾 | `ConnectAsync`、`DisposeAsync` |

- 方法用动作命名，类型用其负责的对象或职责命名。避免 `ProcessData`、`DoWork`、`Helper`、无具体职责的 `Manager`。
- 同一概念使用同一名称：`Waveform` 是波形资产，`Pipeline` 是节点图，`Template` 是可实例化模板，`Session` 是一次运行，`Lease` 是占用租约。波形资产使用 `Waveform` 命名，避免与玩法模板混用 `Preset`。
- 使用 `View`／`ViewModel`、`Node`／`Processor` 等已有职责后缀；不为所有类型添加 `Model` 或 `Service`。
- 常用缩写按单词书写：`Id`、`Json`、`Gatt`、`Rpc`、`Pcm`，不写 `ID`、`JSON`、`GATT`。框架或协议已定义的名称保留原样。
- 使用 `cancellationToken` 表示取消参数，通常放在参数列表末尾。设备标识、节点标识等写出对象，如 `deviceId`、`nodeId`；只在上下文唯一且很短时使用 `id`。
- 数值名称体现含义和单位：`durationSeconds`、`elapsedMilliseconds`、`frequencyHz`、`strengthRatio`、`strengthPercent`。不要用同名变量混存 0–1 与 0–100 两种量程。
- `i`／`j` 用于短索引循环，`x`／`y` 用于坐标；简单查询可使用短 lambda 参数。跨多行或有多个相似对象时使用完整名称。
- `TryGet`／`TryParse` 表示预期失败通过返回值表达；失败属于状态冲突或 I/O 错误时使用明确操作和异常，不用 `Try` 掩盖故障。
- 对外协议键、节点稳定类型键、本地化键和文件名独立于 C# 符号；重命名类型时不要顺带改变存储或线上的标识。

## 字段、变量与属性

- 字段保存对象拥有的状态或依赖。依赖、锁和不重新赋值的集合引用使用 `readonly`；资源确实需要替换或延迟初始化时保留可写字段。
- 不使用公开可变字段。只读 Avalonia 注册字段等框架元数据按框架约定公开。
- 一个字段声明只声明一个变量。用 `const` 表达编译期常量，用 `static readonly` 表达共享且运行期创建的值，不把跨设备或跨会话可变状态放入静态成员。
- 省略多余的 `this.`，仅在消除名称歧义或表达必须的调用对象时使用；调用扩展方法需要显式接收者，如 `this.FindResource(...)`。
- 局部变量尽量靠近首次使用，作用域尽量小。通常使用 `var`；基础类型变量、需要强调的类型边界，以及使用 `new()`／`[]` 初始化时写出类型。避免两边都隐藏类型，如 `var options = new()`。
- 属性用于廉价、可重复读取的状态；普通 getter 不执行 I/O、不改变状态、不推进序列。需要克隆、昂贵计算或有时效的捕获使用 `Snapshot()`、`CaptureAsync()` 等方法。
- 派生状态直接计算，不维护第二份可变副本。对外只读属性使用 `{ get; }` 或 `{ get; private set; }`；配置值优先使用 `init` 或不可变记录。
- 简单属性和简单 getter／setter 保持单行；验证、通知多个属性、持久化或多步修改使用展开的访问器。
- UI 可变属性通过 `Set` 发出通知，图修改通过所属编辑器的编辑入口执行。参数变化更新现有对象，不以重建节点／表单代替状态更新。
- 返回集合时明确所有权：对外读取用 `IReadOnlyList<T>`／`IReadOnlyDictionary<TKey, TValue>`，绑定集合用 `ObservableCollection<T>`。只读接口不代表底层不可变；跨线程或持久化边界需要稳定数据时创建快照。

```csharp
private string _name = "";
private double _strengthLimit = .6;

public string Name { get => _name; set => Set(ref _name, value); }
public bool HasName => !string.IsNullOrWhiteSpace(Name);
public double StrengthPercent => StrengthLimit * 100;

public double StrengthLimit
{
    get => _strengthLimit;
    set
    {
        if (!double.IsFinite(value) || value is < 0 or > 1)
            return;
        if (Set(ref _strengthLimit, value))
            Raise(nameof(StrengthPercent));
    }
}
```

## 方法与职责

- 一个方法完成一个可命名的操作，保持同一抽象层次。公开入口表达流程，细节交给拥有对应状态的对象或私有方法。
- 有独立状态、规则或生命周期的职责提取为组合对象；仅拆几行计算时优先私有方法。不为单一实现或纯数据提取接口。
- 不以行数作为硬限制。约 40–60 行的方法、超过约 300 行的类型应检查职责；纯表格／协议定义不因长度强拆。清理流程可更长，保持执行顺序与异常边界可见。
- 使用 guard clause 提前处理无效状态，避免多层嵌套。预期的 UI 可用性由命令状态表达；底层仍验证不变量。
- 参数表达业务输入，不使用多个含义不明的布尔参数控制不同流程；必要时使用具名参数、枚举或有明确含义的配置记录。
- 可选参数只表达稳定的默认值，`null` 的含义必须清楚。避免让同一 `null` 同时表示“未选择”“保留原值”和“清空”。
- 局部函数用于单个算法中短小、紧密相关的步骤；多个入口复用或拥有长期状态时移到成员方法／组合对象。静态工具方法只用于无实例状态的转换与校验。
- 测试通过行为验证边界，不为拆分出的每个私有步骤分别建立镜像测试。

## C# 语言特性

- 使用当前项目启用的语言特性，不为语法便利提高语言版本或引入预览开关。
- 无继承需求的具体类使用 `sealed`。只有真正需要多态的行为才使用接口／抽象类，避免为了复用少量代码创建继承层次。
- `record` 表达配置、消息和值快照，`class` 表达有身份、状态或资源的对象。记录中的数组／集合仍需按所有权管理，不假设记录自动深度不可变。
- 小型纯值且复制语义明确时才使用 `readonly record struct`／`readonly struct`；不为假定的性能收益将资源或大型状态改成结构体。
- 主构造函数适用于少量依赖、简单初始化的小型对象；需要参数验证、订阅事件、资源所有权或多阶段初始化时使用普通构造函数。同一依赖不要同时保留主构造函数捕获和后备字段两份存储。
- 表达式成员用于单一、简短表达式。出现多步修改、清理、分支或副作用时使用方法体；不要将复杂流程压成表达式。
- 使用模式匹配进行类型／范围判断，使用 `switch` 表达式进行短小的值映射；执行动作或复杂分支使用 `switch` 语句。嵌套三元表达式改为具名步骤。
- 类型可从赋值目标明确看出时使用 `new()` 和集合表达式；调用点无法看出对象类型时写完整构造类型。避免为了省字符叠加类型推断、强制转换和空值抑制。
- 开启可空引用检查。通过分支、模式或 `TryGetValue` 收窄空值；`!` 仅用于确已建立、编译器无法追踪的不变量，并让证明就近可见。不用 `!` 处理外部输入。
- LINQ 用于查询和纯转换；有 I/O、顺序依赖或副作用的流程使用循环。跨 `await`、重复枚举或捕获可变集合时按需要物化；不在每帧热路径中随意增加分配。
- 使用集合初始化器／`with` 更新值配置；不要在转换表达式中顺带修改原对象。
- 使用 `nameof` 引用 C# 成员，不用它生成需要稳定保存的协议／存储键。不用反射广播 ViewModel 属性或代替明确的类型分派。

## 异步、并发与资源

- 默认返回 `Task`／`Task<T>`。接口要求或已确认的同步高频完成路径才用 `ValueTask`；调用方按一次消费处理，不将其随意缓存或重复等待。
- `async void` 仅限框架事件或 `ICommand.Execute` 等必须返回 `void` 的入口，异常在入口明确处理。其他异步操作可等待、可跟踪。
- 不用 `.Wait()`／`.Result`／`GetAwaiter().GetResult()` 阻塞异步流程。不用 `Task.Run` 包装本来就异步的 I/O。原生同步入口必须桥接异步诊断时，桥接仅留在无 UI 消息循环的入口边界，并注明原因。
- `_ = SomeAsync()` 必须有明确的异常观察和生命周期归属；设备写入、保存、停止与释放不能因丢弃任务而跳过等待。
- Core、Pipelines、Remote 和平台服务中不依赖同步上下文的等待使用 `ConfigureAwait(false)`；App 中需要继续更新 UI 的代码保留 UI 上下文，后台回调通过 Dispatcher 进入 UI。
- 取消参数向下传递；只将对应取消令牌触发的取消作为预期退出。停止／清理是否忽略调用者取消在操作边界明确决定，不误吞其他取消或故障。
- 用单调时钟计算时长，用 `DateTimeOffset` 表达时间点，优先注入 `TimeProvider`。不通过累计 UI Tick 估算会话计时。
- 独立操作可并行，存在输出顺序或共享状态时串行。`lock` 内不等待异步任务；`SemaphoreSlim.WaitAsync` 成功后立即进入 `try/finally` 释放。
- 资源所有者负责释放，临时资源使用 `using`／`await using`。停止、归零、释放占用的顺序直接可见；失败时继续必要清理并保留原始错误和清理错误。
- 同步策略与所保护的状态放在同一职责中。线程安全容器只保证容器操作，不替代跨多个状态的不变量或设备操作锁。

## 异常与校验

- 文件、网络、协议和硬件边界验证类型、范围、大小、枚举与有限数值；内部方法依赖的前提应在其所属边界建立。
- 预期失败用返回值／明确状态；异常用于无法完成操作的状态冲突、无效输入与 I/O 故障。不要为更新提示文案主动抛异常。
- 仅在能恢复、补充上下文、清理或形成 UI／协议错误边界时捕获异常。重新抛出使用 `throw;`，不使用 `throw error;` 丢失原始抛出位置。
- 重试、取消和失败采用有语义的状态，不以成功值、非零默认值或空集合伪装故障。特别是已连接输入失效时归零等待。
- 不使用无说明的空 `catch`。预期且可忽略的异常使用具体类型／过滤条件，并简要说明原因；日志包含诊断信息，不包含凭据或原始敏感数据。
- 用户可见错误使用已有本地化错误类型；UI 文案只通过 JSON 本地化键获取。异常参数保留数值与标识，不拼接无法随语言切换的文案。

## 排版与注释

- UTF-8、LF、文件末尾换行；C# 四空格，XAML／JSON／项目文件两空格，不使用 Tab。
- C# 花括号另起一行。一行一条执行语句、一个字段声明；简单属性中的 getter／setter 是紧凑书写的例外。
- 简短且只有一条简单语句的 guard／循环可以不加花括号；条件或语句跨行、存在嵌套或任一分支有多步行为时加花括号，`if/else` 的成组分支保持一致。
- 方法之间和不同逻辑步骤之间留一个空行；连续简单属性可不留空行。不用空行分开每条赋值或每个返回值。
- C# 行长以约 120 字符为参考，超出时按语义换行，调用参数和条件沿用一致缩进。简单属性、声明式注册／数据表可保持完整一行，不为凑长度拆碎名称和表达式。
- 简单对象初始化器和 `with` 可保持单行；多个需要分别阅读的配置项展开。多步 `try/catch/finally`、并发与清理流程不压成一行。
- 注释解释不变量、单位、协议约束、线程／资源所有权以及不明显的原因，不复述语句。独立组件需要时用简短 XML 摘要说明职责，不要求为每个公开属性生成模板注释。
- 不保留注释掉的实现、无跟踪信息的 TODO、历史变更记录或已失效的兼容说明。

## Avalonia XAML 与 UI

- 同一个控件的大多数属性保持在同一行，不采用每个属性一行的机械排版。根元素的命名空间、长绑定或明显降低可读性的声明可按逻辑换行；子内容、模板与复杂属性元素展开。
- 属性顺序：身份／类型（`x:Name`、`x:DataType`），布局与位置，内容／绑定／命令，状态与交互，语义样式，提示与无障碍。属性少时不为顺序单独制造大范围 diff。
- 复用语义样式和组件。颜色来自 `Palette.axaml`，尺寸来自 `Metrics.axaml`；功能范围、通道索引和输入长度等业务参数不当作外观尺寸抽成资源。
- 用 Grid／WrapPanel 的共享间距组织布局，不加入空白行列占位。绑定所属 ViewModel，复用组件明确自己的属性入口，不覆盖继承的 DataContext 来模拟组件 API。
- 文案使用 `{l:Loc Key}`，避免用于标识控件的冗余文字。控件名称表达操作或领域，如 `WaveNameInput`；只有绑定、事件、测试或控件查找确有需要时命名。
- Code-behind 只处理视图职责，如指针坐标、焦点、文件选择器和窗口生命周期；业务状态、设备操作与配置规则归对应对象。

## 测试与检查

- 测试名描述触发条件与预期行为，使用 `PascalCase`，如 `FailedInputStartupClearsRunStateAndAllowsAFreshRun`；测试用例不强制 `Async` 后缀，异步辅助操作仍使用该后缀。按领域放置测试，不以实现文件或辅助类数量决定测试数量。
- 每个测试聚焦一项行为；需要证明同一生命周期不变量时可涵盖启动、失败、重试与清理。准备、执行、断言用空行区分，不重复添加分段注释。
- 使用确定性替身、可控时钟或可等待信号；必须检查后台完成时使用有上限的等待，避免任意延时与无限循环。
- 断言结果、状态、所有权、错误保留和必要的对象身份；不测试私有方法名或源码排版。不以反射访问生产实现细节代替可观察行为。
- 构建与现有分析器负责可机械检查的规则；成员放置、职责划分和命名含义由代码审查检查。不为了消除风格建议批量压制诊断或改写未涉及的代码。
- 文档／格式修改运行适用的静态检查；行为变更运行相应构建与回归测试，遵循项目默认不例行 publish 的约定。

还原依赖后，运行 `scripts/check-style.ps1` 检查全解决方案，使用 `-Fix` 应用可自动修复的规则并审阅差异。`scripts/verify.ps1` 包含该检查。项目启用构建期代码风格分析，已配置规则为 warning，结合 `TreatWarningsAsErrors` 阻止不符合规则的改动；不通过批量压制诊断绕过约定。
